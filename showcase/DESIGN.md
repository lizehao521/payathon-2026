# API Relay 参赛作品展示站 · 设计规范

> 状态：defined（已按用户需求与 frontend-design 完成设计决策，编码沿用本方向）

## 概述

- **用途**：PAYATHON 2026 参赛作品的对外展示站。让评委在 60 秒内看懂「api-relay 是什么、解决了什么、支付链路怎么跑通、商业化怎么闭环」，并留下可点击的交互证据。
- **受众**：赛事评委（产品完整度 / 支付集成 / 商业化 / 影响力）、潜在商家、Agent 开发者。
- **视觉方向**：**工业仪表 × 票据编辑风（Industrial Meter × Receipt Editorial）**。产品本质是「管道 + 计量 + 收费」，所以视觉语言取自机房面板、计量表尺、热敏小票与打孔纸边，而不是通用的 AI 渐变。
- **主要差异点**：整站把「402 待支付 → 支付凭证 → 200 交付」做成一条**可点击推进的真实状态机**，并把门店次数包做成**可核销、可归零、可续购的票据实物感卡片**。不是截图罗列，而是让评委亲手触发一次。
- **反模式**：紫色渐变、玻璃拟态堆叠、居中三段式 hero、无意义的 3D 球体。

## 字体排版

- **Display（拉丁/数字）**：`Bricolage Grotesque`，700/800，字距 `-0.04em`，用于超大标题与数字。
- **中文正文**：`Noto Sans SC`，400/500/700，行高 1.75，正文 16–17px。
- **等宽数据**：`JetBrains Mono`，400/500/700，用于代码、状态、金额、单号、计数，字号 12–14px，字距 0.02em。
- **字号阶梯**：Hero 56/72/88px（clamp）；区块标题 32/44px；卡片标题 20/24px；正文 16/17px；标签 11/12px（uppercase + 0.18em 字距）。
- **中文回退**：`"Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`；Display 回退到 `"Bricolage Grotesque", "Noto Sans SC", sans-serif`。
- **原则**：标题紧、正文松；数字一律等宽；标签全大写小字号制造仪表铭牌感。

## 布局与响应式

- **容器**：`max-width: 1240px`，左右 24px（移动端 20px）。
- **网格**：12 列桌面栅格；区块采用不对称分栏（如 5/7、4/8），避免均分三段。
- **页面层级**：固定顶栏（56–64px，滚动后加背景模糊与下边框）→ Hero → 指标带 → 双赛道 → 402 演示 → 门店闭环 → 降损层 → 技术底座 → 参赛信息 → CTA/页脚。
- **节奏**：区块垂直间距桌面 120px、移动 72px；每个区块有独立的编号铭牌（01–07）。
- **移动端**：≤ 900px 全部单列；导航折叠为菜单按钮（可展开，键盘可操作）；票据卡片取消旋转；终端卡片横向滚动改为自动换行；触控目标 ≥ 44px；`env(safe-area-inset-bottom)` 仅用于底部 CTA 的 CSS 文件。

## 通用基础组件

- **按钮**：
  - Primary：信号绿实底 + 深色文字 + 2px 硬阴影（`4px 4px 0`），hover 位移 1px、阴影收缩；active 完全压下。
  - Ghost：1px `--line` 描边 + 次文本；hover 边框转信号绿。
  - Disabled：透明度 0.4 + `cursor: not-allowed`，不改变布局。
  - Focus-visible：2px 信号绿外描边 + 2px 偏移，所有可交互元素统一。
- **卡片**：`--ink-2` 底 + 1px `--line` 边 + 16–20px 圆角；票据卡用 `--paper` 底、0 圆角、打孔边与锯齿边。
- **标签/状态灯**：10px 圆点 + 等宽大写文字；状态：`idle`（灰）、`pending`（琥珀，呼吸动画）、`ok`（绿）、`fail`（红）。
- **终端**：标题栏含三个状态点与路径；行首 `+4ms ok route` 式时间戳前缀；错误行用琥珀/红。
- **空/错/加载**：展示站无异步数据，交互模块显式提供「重置」与「重新演示」；不出现无限 spinner。
- **导航**：锚点滚动带 `scroll-margin-top: 88px`；当前区块高亮（IntersectionObserver）。

## 动效与可访问性

- **入场**：Hero 标题按行 `clip-path` 上移 + 80ms 错峰；区块进入视口时 `translateY(18px) → 0`，只触发一次。
- **核心动效**：402 状态机推进（逐行打字感）、票据核销时数字翻动与打孔闪烁、指标数字滚动。
- **性能**：仅 transform/opacity 动画；滚动监听用 IntersectionObserver；`prefers-reduced-motion: reduce` 时全部动画降为 0.01ms，状态机仍可手动推进。
- **可访问性**：所有状态变化用 `aria-live="polite"` 播报；演示按钮有明确 `aria-label`；颜色不作为唯一状态信号（同时有文字/图标）；键盘可完成 402 演示与票据核销全流程。

## 购买与权益（Vibe Pay）

- **区块位置**：门店闭环之后、降损层之前，编号 `04 / BUY A PACK`，导航项「购买次数」。
- **左栏（深色面板）**：商品名、计费模式、支付通道、到账位置、买家身份、价格；主按钮「购买次数包」。
  - 状态：`读取商品`（loading）→ `可购买` / `暂不可购买`；不可购买时必须写明原因（配置中 / 未开通 / 授权缺失），并且不生成订单。
  - 支付态：桌面直接渲染服务端返回的 `purchaseQrCode` 图片；移动端给「在支付宝中打开支付页」按钮，不自动跳转。移动端只按 UA 判断（Android/iPhone/iPad/Mobile/AlipayClient），Windows 触屏桌面即使窗口很窄也展示二维码。
  - 等待态：显示订单号、「我已完成支付」手动确认；后台每 5 秒查询一次，最多 3 分钟；未支付时 `quota/refresh` 的 `NOW_PAY_QUOTA_CONSUME_NOT_FOUND` 属正常，静默回落到 `quota/query`。
  - 接口字段：服务端是严格 schema，`quota/query` 只用 `outProductId` + `buyerId`，`purchase/create` 与 `quota/refresh` 额外带 `outRequestNo`；次数包不支持 `purchase/consult`，多余字段会被 400 拒绝。支付链接约 30 分钟过期，单号只复用 25 分钟内的订单。
- **右栏（米白票据）**：剩余次数、累计/已用、买家身份短号、刷新按钮；未开通时显示「服务未开通，暂不可查询」而不是 0。
- **购买记录**：固定官方图片 + 支付宝扫一扫提示，不做二次编码或跳转。
- **文案原则**：真实扣款由支付宝完成；页面不接触银行卡信息；商品已创建 / 已启用 / 已授权 / 已支付四种状态必须分开表述。

## 该做与不该做

**做**
- 用「计量表尺 + 票据 + 终端日志」三种实物隐喻承载信息。
- 每个卖点都配可验证的数字或可点击动作。
- 深墨底 + 米白纸 + 信号绿/琥珀的高对比三色体系。
- 中文标题用重字重、短句；英文术语与数字交给等宽字体。

**不做**
- 不做紫蓝渐变、发光玻璃、居中大标题 + 三张等宽卡片。
- 不堆砌未经验证的数据；所有数字来自仓库 README / 测试结果，并标注口径。
- 不用纯色块表达状态；不隐藏移动端关键操作。
- 购买区接真实 Vibe Pay 收款，未配置完成时显示「暂不可购买」，不伪造支付成功、订单或余额。
- 402 演示与门店票据仍为模拟链路，必须与真实购买区在文案上区分开。
